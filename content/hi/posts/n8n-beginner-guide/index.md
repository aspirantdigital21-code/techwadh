## n8n क्या है और कैसे चलता है?

n8n (एन-एट-एन) एक लो-कोड ऑटोमेशन प्लेटफ़ॉर्म है। इसके ब्राउज़र एडिटर में ऐप, API, डेटाबेस और AI मॉडल जोड़ सकते हैं। पूरे ऑटोमेशन को **वर्कफ़्लो**, हर स्टेप को **नोड**, शुरुआत कराने वाले इवेंट को **ट्रिगर** और एक बार चलने को **एक्ज़ीक्यूशन** कहते हैं। सर्वर वर्कफ़्लो चलाता है। सेल्फ़-होस्टिंग में SQLite से शुरुआत कर सकते हैं और ज़रूरत के अनुसार PostgreSQL इस्तेमाल कर सकते हैं। [आधिकारिक डॉक्यूमेंटेशन](https://docs.n8n.io/)

![n8n सर्वर, प्रॉक्सी और डेटाबेस का डायग्राम](/n8n-guide/architecture.webp)

| नोड या विकल्प | कब इस्तेमाल करें |
| --- | --- |
| Manual / Schedule Trigger | खुद चलाने या तय समय पर शुरू करने के लिए |
| Webhook / App / Chat Trigger | URL पर रिक्वेस्ट, ऐप इवेंट या चैट से शुरू करने के लिए |
| Edit Fields | डेटा के फ़ील्ड जोड़ने, बदलने या मैप करने के लिए |
| IF / Switch | शर्त के आधार पर अलग रास्ता चुनने के लिए |
| Merge / Loop Over Items | डेटा जोड़ने या बैच में प्रोसेस करने के लिए |
| HTTP Request / Code | API कॉल या अपना डेटा ट्रांसफ़ॉर्मेशन करने के लिए |
| Credentials / Executions | ऐप लॉगिन अलग रखने और हर रन की जाँच करने के लिए |

## Cloud और लोकल सेटअप में से चुनें

**n8n Cloud** में सर्वर मैनेज किए बिना शुरुआत कर सकते हैं। **लोकल Docker** से अपने पीसी पर अभ्यास कर सकते हैं। Docker चालू करके नीचे की कमांड चलाएँ और [localhost:5678](http://localhost:5678) पर ओनर अकाउंट बनाएँ। पोर्ट अपने पीसी तक सीमित रहेगा और नाम वाला वॉल्यूम कंटेनर हटने के बाद भी डेटा रखेगा। n8n के डॉक्यूमेंटेशन में 3.0 से npm इंस्टॉल को deprecated बताया गया है। पुराने `npx n8n` ट्यूटोरियल का कमांड चलाने से पहले अपना वर्ज़न देखें। [Docker docs](https://docs.n8n.io/deploy/host-n8n/install-options/install-with-docker.md) · [npm docs](https://docs.n8n.io/deploy/host-n8n/install-options/install-with-npm.md)

```bash
docker volume create n8n_data
docker run --rm --name n8n -p 127.0.0.1:5678:5678 \
  -e GENERIC_TIMEZONE=Asia/Kolkata -e TZ=Asia/Kolkata \
  -v n8n_data:/home/node/.n8n docker.n8n.io/n8nio/n8n
```

i3 और 8 GB RAM वाले पीसी पर पहले छोटा वर्कफ़्लो और एक ऐप आज़माएँ। असली लोड इस बात पर निर्भर करेगा कि Docker और बाकी ऐप क्या चला रहे हैं। पीसी बंद या स्लीप में जाने पर लोकल ऑटोमेशन रुक जाएगा। लगातार चलाने के लिए मैनेज्ड होस्टिंग या मेंटेन किया हुआ सर्वर चाहिए। AI API का कोटा और खर्च अलग हो सकता है।

## पहला वर्कफ़्लो बनाएँ, बिना API key के
1. नया वर्कफ़्लो खोलें और **Manual Trigger** जोड़ें।
2. **Edit Fields** में दो String फ़ील्ड बनाएँ। `name` में `Rohit` और `status` में `ready` डालें।
3. **IF** जोड़ें। बाएँ String फ़ील्ड में Expression मोड से `{{ $json.status }}` डालें। **is equal to** चुनें और दाएँ `ready` रखें।
4. **true** तरफ **Edit Fields** में `message` की expression `{{ 'Ready to publish: ' + $json.name }}` रखें। **false** तरफ **Edit Fields** में `message` का टेक्स्ट `Skipped` रखें।
5. **Execute workflow** दबाएँ। पहला आउटपुट `Ready to publish: Rohit` आना चाहिए। `status` को `draft` करके फिर चलाएँ। अब `Skipped` आना चाहिए।

![Manual Trigger से IF की दोनों ब्रांच तक](/n8n-guide/first-workflow.webp)

नोड के बीच **items** की सूची जाती है। हर आइटम में JSON फ़ील्ड होते हैं और ज़रूरत पर बाइनरी डेटा भी हो सकता है। कई नोड हर आइटम को अलग प्रोसेस करते हैं। API कॉल गिनने से पहले नोड का व्यवहार देखें। `{{ $json.name }}` मौजूदा आइटम का नाम पढ़ता है। `{{ $now.format('yyyy-MM-dd') }}` आज की तारीख फ़ॉर्मैट करता है। टेस्ट में नमूना आउटपुट पिन करके बार-बार API कॉल करने से बच सकते हैं। [डेटा स्ट्रक्चर](https://docs.n8n.io/data/data-structure/) · [डेटा पिनिंग](https://docs.n8n.io/data/data-pinning/)

## उसी वर्कफ़्लो को Webhook से चलाएँ
1. Manual Trigger की जगह **Webhook** लगाएँ। Method `POST` और Path `demo-intake` रखें।
2. पहले Edit Fields में `name` को `{{ $json.body.name }}` और `status` को `{{ $json.body.status }}` से मैप करें।
3. Webhook का Response Mode **When Last Node Finishes** रखें। **Listen for test event** दबाएँ और **Test URL** कॉपी करें।
4. नीचे अपने Test URL के साथ रिक्वेस्ट चलाएँ। फिर `status` को `draft` रखकर दूसरा रास्ता भी जाँचें। ज़रूरत हो तो दूसरी रिक्वेस्ट के लिए फिर से सुनना शुरू करें।
5. असली इंटीग्रेशन के लिए ऑथेंटिकेशन सेट करें, वर्कफ़्लो **Publish** करें और रिक्वेस्ट भेजने वाले ऐप को **Production URL** दें। कार्रवाई से पहले ज़रूरी फ़ील्ड जाँचें। बाहरी ऐप को पहुँचने योग्य HTTPS URL चाहिए। [Webhook documentation](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.webhook/)

```bash
curl -i -X POST 'PASTE_N8N_TEST_URL_HERE' \
  -H 'Content-Type: application/json' \
  -d '{"name":"Rohit","status":"ready"}'
```

## YouTube से Telegram तक असली क्रिएटर वर्कफ़्लो

**RSS Feed Trigger** में अपने YouTube चैनल का फ़ीड URL डालें। पहले टेस्ट करके देखें कि आउटपुट में वीडियो का टाइटल, URL और स्थायी ID किस फ़ील्ड में आते हैं। ID को डिलीवरी लॉग में देखें। Telegram bot को लक्ष्य चैनल में पोस्ट करने की अनुमति दें और पहले निजी टेस्ट चैट में संदेश भेजें। सफल रिस्पॉन्स पर डिलीवरी दर्ज करें। एक साथ कई रन हों तो वास्तविक सिस्टम में भेजने से पहले यूनिक ID रिज़र्व करें और असफल या अनिश्चित डिलीवरी के लिए अलग स्थिति रखें।

![YouTube से Telegram अलर्ट और डुप्लिकेट जाँच](/n8n-guide/youtube-alert.webp)

| प्रोजेक्ट | वर्कफ़्लो |

| Unity बिल्ड अलर्ट | CI में सफल बिल्ड → ऑथेंटिकेटेड Webhook → Telegram |
| फ़ीडबैक ट्रैकर | फ़ॉर्म → फ़ील्ड जाँचें → Sheet या डेटाबेस → साप्ताहिक सारांश |
| सपोर्ट इनबॉक्स | ईमेल → श्रेणी चुनें → टिकट बनाएँ → जवाब का ड्राफ़्ट |

## AI चेन, AI एजेंट और MCP

सारांश या कैप्शन जैसे तय काम के लिए **Basic LLM Chain** से शुरू करें। जब मॉडल को तय करना हो कि कौन-सा टूल इस्तेमाल करे, **AI Agent** लगाएँ। साथ में Chat Model, स्पष्ट निर्देश और शुरुआत में केवल पढ़ने वाला टूल रखें। चैट की पिछली बातें चाहिए तो सेशन मेमरी जोड़ें। दस्तावेज़ों पर सवाल-जवाब के लिए अनुमोदित डॉक्यूमेंट स्टोर से संबंधित जानकारी ढूँढने का स्टेप जोड़ें। MCP इस्तेमाल करते समय देखें कि कौन-से टूल और डेटा उपलब्ध हो रहे हैं। सार्वजनिक पोस्ट से पहले इंसान ड्राफ़्ट जाँचे। [n8n AI डॉक्यूमेंटेशन](https://docs.n8n.io/advanced-ai/)

## आम गलतियाँ और प्रोडक्शन चेक

| दिक्कत | पहले क्या जाँचें |
| --- | --- |
| शेड्यूल चला ही नहीं | वर्कफ़्लो पब्लिश है या नहीं, टाइमज़ोन और अगला रन |
| Webhook पर 404 | Method, Path, Test listener या Production URL |
| 401 / 403 | क्रेडेंशियल, अनुमति और सही ऐप अकाउंट |
| 429 | API की दर सीमा, बैच साइज़ और रिट्राई में देरी |
| डुप्लिकेट संदेश | इवेंट ID, डिलीवरी लॉग और साथ चल रहे रन |
| आउटपुट खाली | पिछले नोड का JSON और `$json.body` की मैपिंग |

नोड को स्पष्ट नाम दें। API key को नोड की फ़ील्ड या एक्सपोर्ट में हार्डकोड करने की जगह **Credentials** इस्तेमाल करें। अलग **Error Trigger** वर्कफ़्लो बनाएँ और उसे मुख्य वर्कफ़्लो की सेटिंग में जोड़ें। 24/7 सेटअप में HTTPS, रिवर्स प्रॉक्सी के पीछे बाहरी Webhook URL, नियमित अपडेट, एक्ज़ीक्यूशन हिस्ट्री की सफ़ाई और डेटाबेस व एन्क्रिप्शन key का सुरक्षित बैकअप रखें। भारी लोड पर PostgreSQL, Redis और वर्कर वाला Queue Mode देखें। [एरर हैंडलिंग](https://docs.n8n.io/flow-logic/error-handling/) · [होस्टिंग गाइड](https://docs.n8n.io/hosting/)

## चार हफ्तों का सीखने का रोडमैप

**हफ्ता 1** · Manual Trigger और IF की दोनों ब्रांच जाँचें। **हफ्ता 2** · HTTP Request, फ़ील्ड मैपिंग और बैचिंग सीखें। **हफ्ता 3** · एक ऑथेंटिकेटेड Webhook पब्लिश करें और डुप्लिकेट टेस्ट करें। **हफ्ता 4** · AI ड्राफ़्ट, मंज़ूरी और फ़ेल होने पर अलर्ट जोड़ें। किसी टेम्पलेट को चलाने से पहले उसके नोड और ऐप अनुमतियाँ देखें। [वर्कफ़्लो टेम्पलेट](https://n8n.io/workflows/) · [n8n कम्युनिटी](https://community.n8n.io/)

## अक्सर पूछे जाने वाले सवाल

### क्या n8n मुफ़्त है?

### पहला वर्कफ़्लो बनाने के लिए कोड चाहिए?

Manual Trigger, Edit Fields और IF वाला उदाहरण UI में बन जाता है। एक छोटी expression इनपुट में नाम जोड़ती है।

### गाइड का 400 वाला केस असली Webhook में कैसे जोड़ें?

Webhook का response mode **Using Respond to Webhook Node** रखें। पहले IF से नाम जाँचें। खाली नाम वाली शाखा में Respond to Webhook से JSON और HTTP 400 लौटाएँ। वैध नाम वाली शाखा में सामान्य प्रोसेसिंग के बाद HTTP 200 लौटाएँ। [आधिकारिक Webhook गाइड](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.webhook/)
